# NewGetSamples

## 專案狀態

這是歷史 Windows Script Host（WSH）/ VBScript 工具，原始程式標示由 Liang Li-ying 撰寫，時間約為 2007–2009 年。它嘗試從 Windows 電腦收集可疑檔案，並同時執行多項系統清理與登錄修改。

**目前版本不應直接用於日常電腦、正式環境或未經授權的設備。** 程式會終止多個程序、刪除登錄機碼、停止或移除服務／驅動程式、刪除檔案，並可能重新開機。它沒有預覽模式、可靠的復原機制或完整錯誤處理；目前也尚未完成編譯與 Windows 相容性驗證。

本儲存庫目前只適合用來保存、檢視及審查歷史程式碼。不要把它視為已維護、已驗證或可安全部署的防毒產品。

## 歷史背景與典藏目的

依作者回憶，這支工具是早年任職於資安軟體代理商期間所撰寫。當時作者需要有效率地協助處理客戶遇到的問題，尤其是移除隨身碟病毒及其他常見惡意程式，並將樣本收集回來供後續分析，因此開發了這個工具程式。

原始程式多年來失傳於網際網路，也沒有留下可查的歷史紀錄。作者希望將程式與這段背景一併放上 GitHub，作為個人工作歷程及早期資安實務的歷史紀錄。這個儲存庫的首要目標是保存原貌、補足脈絡，而不是重新包裝成目前可用的惡意程式清除工具；程式年代、相依環境及破壞性行為仍須以本文件後續說明為準。

## 功能概觀

程式的目標是從設定清單找出檔案、登錄值、服務及驅動程式，將部分檔案複製到桌面上的樣本資料夾，並輸出執行記錄。除此之外，它還會直接處理多個系統範圍的自動啟動位置、可見檔案設定與 `hosts` 檔案。

這些行為不是唯讀掃描。即使使用者選擇略過其中一個確認視窗，程式仍會繼續其他清理步驟；程式內的 `On Error Resume Next` 也可能讓錯誤被略過，無法據此判斷操作成功或失敗。

## 執行流程

以下依程式目前的控制流程整理。這是程式碼行為摘要，不代表建議執行順序：

1. 顯示備份資料、關閉其他應用程式的警告，使用者選擇繼續後才進入主流程。
2. 連接本機 WMI、登錄服務與 Windows Script Host 物件，並在桌面建立／追加 `gvsLog.txt`。
3. 讀取 Windows 版本資訊及開機狀態。若偵測到一般開機模式，會詢問是否重新啟動；確認後會呼叫重新開機。
4. 建立桌面上的 `VirusSample` 資料夾，並依序處理 IFEO 登錄子機碼、程序與 `%TEMP%\List.txt` 中的項目。IFEO 清理會刪除該路徑下列出的子機碼，不會先依清單判定是否為惡意項目。
5. 清理 `ShellExecuteHooks` 與 `ShellServiceObjectDelayLoad` 的部分登錄值及其關聯檔案。
6. 搜尋可移除磁碟、固定磁碟及 RAM 磁碟上的 `autorun.inf`，並處理檔案中所指向且存在的檔案。
7. 設定顯示隱藏檔案相關登錄值，並詢問是否將 `hosts` 檔案重設成僅含 localhost 項目的內容。
8. 嘗試使用 `%TEMP%\rar.exe` 將樣本資料夾及記錄壓縮成桌面上的 `VirusSample.rar`。
9. 記錄數個自動啟動登錄位置的值，最後詢問是否重新啟動電腦。

程式中呼叫卡巴斯基掃描及清理暫存資料夾的程式碼目前均被註解，主流程不會執行它們。不要因為程式名稱或舊註解而假設它會進行完整防毒掃描。

## 輸入與清單格式

主流程會讀取 `%TEMP%\List.txt`；檔案不存在時，記錄會寫入 `No List!!!!`，但其他系統清理仍可能繼續。每一行以星號（`*`）切分欄位，第一欄是操作名稱。程式碼辨識下列名稱：

| 操作名稱 | 程式嘗試執行的動作 |
| --- | --- |
| `[StopService]` | 停止指定服務，並嘗試將啟動模式改為停用。 |
| `[DelService]` | 停止、停用並嘗試刪除指定服務；可連帶處理一個檔案路徑。 |
| `[DelDrivers]` | 停止、停用並嘗試刪除指定系統驅動程式；可連帶處理一個檔案路徑。 |
| `[DelRegValue]` | 嘗試刪除指定登錄值，並可連帶處理一個檔案路徑。 |
| `[ModRegValue]` | 依既有登錄值類型，嘗試修改支援的登錄值。 |
| `[DelSpecFiles]` | 將指定檔案交給檔案處理程序，嘗試複製、刪除或在刪除失敗時改名。 |

這張表只描述程式碼中的分派名稱與大致副作用，不是可直接執行的操作範例。**儲存庫刻意不附上 `List.txt` 範例或可套用於真實系統的刪除清單。** 清單可觸發登錄、服務、驅動程式及檔案變更；任何候選清單都必須由具備系統管理與事件應變經驗的人員逐行審核，並且只在明確授權的隔離測試環境評估。

程式沒有欄位數、路徑、登錄 hive、操作目標或值型別的完整驗證。格式錯誤或欄位不足時，錯誤可能被略過；包含 `*` 的資料也會被當成欄位分隔符，沒有跳脫機制。若檔案含有未知操作名稱，程式只記錄 `Unknown list format`，然後繼續。

## 系統變更與資料風險

### 程序與登錄

- `StopProcess` 會查詢本機所有 WMI 程序，並嘗試終止除 `NGS1xList.exe`、`winlogon.exe` 以外的每一個程序。它不是只停止清單指定的程序；這可能造成工作遺失、系統介面中斷或應用程式損毀。
- `delIFEO` 會刪除 `Image File Execution Options` 下列舉到的所有子機碼。此位置也可能包含合法的除錯器或系統設定。
- 自動啟動相關登錄清理會依程式內的例外名稱保留部分值，並嘗試刪除其他值及關聯檔案。例外清單不是惡意程式判定機制。
- `showAll` 會寫入目前使用者與本機電腦的登錄值；這不是唯讀動作。
- 修改或刪除登錄值前，程式沒有建立可供復原的登錄備份。

### 檔案與樣本

- 檔案處理程序會嘗試先複製到桌面 `VirusSample`，再刪除原始檔；若檔案仍存在，會嘗試改名為 `.ngs`。複製及刪除的結果不應只依賴記錄檔判定，尤其檔案目的路徑的組合方式需要額外驗證。
- `DelAutorun` 可能處理所有符合程式所列磁碟類型的磁碟，不限於系統磁碟。
- 重設 `hosts` 時，程式會先把非註解內容寫入記錄，再刪除原檔並建立最小內容；記錄不是可直接還原的備份，原有註解及設定可能遺失。
- 壓縮命令使用固定密碼 `virus`，且外部 `rar.exe` 必須已存在於 `%TEMP%`。固定密碼不適合保護敏感樣本；壓縮檔可能包含可執行惡意檔案，應視為高風險資料處理。
- 樣本複製、壓縮及記錄都沒有雜湊、來源驗證或安全交付流程。

### 重新啟動與失敗處理

程式可能在偵測到一般開機模式時，以及完成主流程時詢問重新啟動。部分檔案操作可能因系統鎖定而失敗，但程式大量使用 `On Error Resume Next`，可能在未清楚呈現錯誤的情況下繼續執行。記錄中的方法回傳碼也不能取代逐項驗證。

## 執行需求與限制

程式是 Windows 專用的舊式 VBScript，依賴 Windows Script Host、WMI、登錄提供者及多個 COM 元件。需要的權限會依實際操作而異；修改 HKLM、服務、驅動程式或受保護檔案通常需要系統管理權限。此儲存庫沒有包含 `List.txt`、`rar.exe` 或其他第三方工具。

目前沒有已驗證的 Windows 版本、32／64 位元相容性資料、安裝程序、測試套件、模擬模式或自動化 CI。原始碼年代久遠，不應推定它能在目前的 Windows 版本正常運作。

### 已知程式碼阻斷與待查項目

1. 原始碼宣告了兩個同名的 `Sub ListValue`。VBScript 程序名稱不支援這種重複宣告；這很可能造成剖析／編譯錯誤，必須在有 Windows Script Host 的環境確認。不要只為了讓它通過剖析而任意刪除其中一個版本，因為兩者內容與用途不同。
2. 全域及各程序中的 `On Error Resume Next` 會隱藏許多錯誤，錯誤後續狀態也未必可靠。
3. `ListValueOne` 使用 `objReg`，但主流程建立的登錄物件名稱是 `oReg`；該函式目前未見主流程呼叫，仍需確認是否為未完成或過時程式碼。
4. `DelSpecFiles` 的複製成功檢查會把目的資料夾與來源路徑直接串接，對完整路徑可能產生不正確的檢查路徑。
5. `RenameFiles` 的 WMI 改名呼叫使用 `Rename` 名稱，而非傳入的 `fileName`；在目前的錯誤處理方式下，改名失敗可能不明顯。
6. 程式透過 `%TEMP%\rar.exe` 呼叫外部壓縮程式，沒有檢查檔案是否存在、版本、來源或執行結果。

以上項目是依靜態閱讀提出的審查事項，尚未在 Windows 上驗證。尤其第一項可能讓整個腳本無法執行，是任何進一步測試前都要先確認的問題。
